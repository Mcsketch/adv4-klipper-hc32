# Roadmap

Brainstorm, 2026-11-03. Order inside each area is the suggested build order.
"Have" lists what the printer already does, so nothing gets built twice.

## Where it stands

Have: Klipper on the MCU, Moonraker 0.11 (job queue, history, object
processing on), Mainsail, `exclude_object`, `pause_resume`, `respond`,
`firmware_retraction`, the panel with Print / Preheat / Filament / Tools
menus, `HOME_XYZ`, `PRINT_START` / `PRINT_END`, `LOAD_FILAMENT` /
`UNLOAD_FILAMENT`.

Missing that matters: no `M600`, `[bed_mesh]` present but no probe,
no recorded slicer choice, no pressure advance or input shaper calibration.

Known limits that cap everything below:

| Limit | Value | Effect |
|---|---|---|
| Hot end flow | slips near 4.8 mm³/s | 0.2 x 0.45 mm lines top out near 53 mm/s |
| Speed cap (Caleb) | 60 mm/s incl. travel | until lifted |
| Z | 5 mm/s (10 stalls up), whines | known issue, HARDWARE.md |
| SoC | V3S, ~55 MB RAM, busybox | printer-side code must be tiny C |

## 1. Job info on the panel (G-code processing)

Goal: send a job, the panel shows the model, an honest finish time and the
numbers that matter, from the first layer to the last.

| ID | Item | Approach | Status |
|---|---|---|---|
| J1 | Slicer metadata reaches Moonraker | Slicer header must match Moonraker's PrusaSlicer pattern (`; generated by X on DATE at TIME`, Orca and its forks do). Check one real sliced file: `slicer`, `estimated_time`, `thumbnails` in `/server/files/metadata`. Checked 2026-11-03 on `ad4_test_plate` (Orca 2.4.2): `slicer` OrcaSlicer 2.4.2, `estimated_time` 1413, filament and both thumbnails all reported. | done |
| J2 | Accurate time | Run [klipper_estimator](https://github.com/Annex-Engineering/klipper_estimator) as the slicer's post-processing step. It simulates Klipper's own motion planner with this printer's limits (read from Moonraker) and rewrites the estimate and `M73` progress. Usually within a few percent; slicer estimates on Klipper are often 10-30 % off. Installed and wired into the S2 process presets; test plate 22m 24s (Orca) vs 23m 33s (estimator). Real print 2026-11-03 (`ad4_test_plate`, Orca CLI + klipper_estimator): estimate 23m 33s, print_duration 23m 50s (1.2 % long); heating and homing add about 3.5 min on top. | done |
| J3 | Panel: remaining time and finish clock | Remaining = estimate x (1 - p) x ((1 - p) + p x drift), where p is `M73` progress and drift is `print_duration` / (estimate x p), clamped 0.5-3; no estimate: extrapolate from elapsed after 5 %. Until the first extrusion it shows "HEATING, THEN" and the full estimate. The clock comes from Moonraker's `Date` header (the SoC has no RTC) and `/etc/localtime` (America/Denver, copied to the SoC). Installed 2026-11-03. Real print 2026-11-03 (`ad4_test_plate`, Orca CLI + klipper_estimator): panel showed 5 min left and done at 18:43 at 79 %; it finished 18:43. | done |
| J4 | Panel: model thumbnail | Slicer embeds a PNG thumbnail; Moonraker extracts it to `.thumbs/`. The panel fetches it over HTTP and decodes it with a vendored single-file decoder (lodepng or stb_image, static, no libs). Large one on the job screen, small one in the Print list. Done with stb_image (PNG only): 160 px on the job screen, 128 px on the file screen, transparent pixels blended. Tested with an uploaded file. Print list (2026-11-03, md5 aaea5fdf): 56 px thumbnail per row (box-filtered down), second line is the estimate and grams from the slicer, or the file size when there is none. | done |
| J5 | Panel: job screen | Thumbnail, name, progress bar, layer N / M, elapsed, remaining, finish clock, filament used (m and g), speed and flow %, temps with targets, fan. Installed 2026-11-03 with all of these except grams and speed / flow % (those come with J6). Layer N / M needs `SET_PRINT_STATS_INFO`, which the S2 machine preset now sends. Real print 2026-11-03 (`ad4_test_plate`, Orca CLI + klipper_estimator): layer N / 100, progress, elapsed, fan and filament matched Moonraker. | done |
| J6 | Panel: tune during a job | Built 2026-11-03: a TUNE button between PAUSE and CANCEL opens rows of - / + for speed (`M220`, 10 % steps, 20-100 %: down only, because the 60 mm/s cap is in the slicer and `max_velocity` is 150), flow (`M221`, 2 %, 80-120 %), Z offset (`SET_GCODE_OFFSET Z_ADJUST MOVE=1`, 0.02 mm, within +/-1 mm), nozzle (5 C, 180-260) and part fan (10 %; the slicer's next fan command overrides it). A value off its default is amber. On the panel 2026-11-03 (md5 7b89be33). Left: Caleb tries each row during a print. Pressure advance waits for Q-series calibration. | wip |
| J7 | Panel: cancel one object | On the panel 2026-11-03 (md5 cd2f650a): TUNE > OBJECTS draws the bed (220 x 200 mm, back at the top) with each object's polygon from `exclude_object`, the current one in blue, skipped ones dim, and a button per object (up to 6). Two taps send `EXCLUDE_OBJECT NAME=`. The last object left is not offered. Previewed against a mock Moonraker; left: skip one object on a real multi-object print. | wip |
| J8 | Panel: end of job | On the panel 2026-11-03 (md5 aaea5fdf): after a job the home screen shows a card until OK is tapped: thumbnail, DONE / CANCELLED / FAILED, the name; then printed time, estimate +/- % (complete), time with heat-up, filament m and g, cost (material + machine hours). A failed job shows Klipper's message instead. REPRINT (two taps) starts the same file. Riff on complete, fail cue on error. Rates live in Moonraker's database (`ad4` / `cost`, from FreeCAD's PLA price, density and MachineRate); see HOW-IT-WORKS. Previewed against a mock Moonraker; left: see it after a real print. | wip |
| J9 | Live layer preview | Panel draws the current layer's toolpath from the G-code as it prints (outline, nozzle position). Needs a cheap way to read the layer from the file without loading it into the SoC's RAM. | idea, stretch |

## 2. Camera and light

| ID | Item | Approach | Status |
|---|---|---|---|
| C1 | Find out what the camera gives | Done 2026-11-03: UVC "USB 2.0 PC Camera" (058f:3841) on `/dev/video0`. MJPEG 160x120 to 1280x1024 (incl. 1280x720) at 30/25/20/15/10/5 fps, frames carry their own Huffman tables (browsers show them as-is); YUYV up to 1600x1200 at 9 fps. Auto exposure gives about 10 fps in the dark. The SoC's kernel 3.4 uses a 32-bit `timeval` in `v4l2_buffer` (68 bytes): build V4L2 code with `-D_TIME_BITS=32 -D_FILE_OFFSET_BITS=32`, or `VIDIOC_DQBUF` fails with ENOTTY. | done |

Up to 4 clients, a slow one skips frames. Opens the camera on the first request and closes it 10 s after the last, so it costs nothing while nobody watches. Measured: snapshot 1.3 s cold, stream about 9.4 fps in the dark, about 1 % CPU, 2.4 MB RSS. Started from `klipper-boot.sh` (`CAM_PORT`). | done |
| C3 | Camera in Mainsail | Done 2026-11-03: Moonraker `[webcam ad4]` (mjpegstreamer, 16:9) with `/webcam/stream` and `/webcam/snapshot`, which Caddy :8095 proxies to the printer (browsers can't reach 192.168.100.x), so it works over Tailscale like Mainsail. | C4 | Timelapse | 2026-11-05: moonraker-timelapse on the ProDesk (`host/install-host.sh` sets it up). Rendered at the end of the job (30 fps, `~/printer_data/timelapse`), in Mainsail's Timelapse tab. Frames and render tested without a print. | done, untested on a print |
| C5 | Light | Done 2026-11-03 (Caleb at the printer): PA4 is the chamber light. `[output_pin light]`, software PWM at 1 kHz; the camera saw it dim at 30 % and full at 100 %. `PRINT_START` turns it on, `PRINT_END` off; Mainsail shows it under Miscellaneous. | C6 | Failure detection | Spaghetti detection from the camera (Obico self-hosted, or a lighter model on the ProDesk). Watch the ProDesk's memory: it has OOM-crashed before. | idea, stretch |

## 3. Slicer

Need: Klipper and Moonraker upload, thumbnails, object labels, by-object
sequence, single-extruder multi-material, colour painting, per-object and
height-range modifiers, calibration tools, editable profiles kept in git.

| Slicer | For | Against |
|---|---|---|
| **OrcaSlicer** | All of the above; the best calibration suite (PA, flow, temperature, retraction, max volumetric speed, VFA); first-class Klipper support; very active. | Another install. Check it has a CC2 profile so both printers stay on one slicer. |
| ElegooSlicer (now) | Already set up on the ASRock for the AD4 and the CC2; it is an Orca fork, so most features match. | Lags Orca; Elegoo-first defaults; one more fork between us and fixes. |
| PrusaSlicer | Solid, good multi-material and sequential. | Fewer calibration tools, weaker Klipper extras. |
| Bambu Studio, Cura | | Klipper support and profile control are weaker. |

Decision (S1, 2026-11-03): OrcaSlicer for the AD4 and the CC2.
